## 1. Competitor images utha kar lagana — nahi kar sakta

Yeh copyright infringement hoga — competitor sites ya Google se product/device photos utha kar apne commercial plugin mein bechna legally risky hai (device renders bhi manufacturer-owned hote hain). Main is mein madad nahi kar sakta. Lekin jo maine pehli MD file mein likha tha wahi asal professional solution hai: **har model ki apni unique photo ki zaroorat hi nahi** — competitors bhi 3,000+ models ke liye alag-alag real photo nahi rakhte, series-level generic image kaafi hoti hai (customer bas confirm karta hai "haan yeh mera model hai", glamour shot nahi dekhta). Isay MD2 mein detail se likh raha hoon.

## 2. Pricing combinations ka asal masla — yeh sabse important sawal hai

Aap ka andesha sahi hai: 196 models × 40 repairs = **7,840 combinations**. Har ek ko manually price dena ناممکن hai. Iska sahi professional solution ek hi cheez hai: **Tier-based pricing with cascading override** — yehi system hai jo RepairPlugin/RepairBuddy jaise tools use karte hain.

Concept simple hai:
- Har model ko ek **Price Tier** assign hoti hai (Economy / Mid-Range / Flagship / Premium). Yeh price ka category hai, image ka nahi.
- Aap sirf **40 repairs × 4 tiers = 160 prices** set karte hain (ek grid screen par) — yeh aap ka base pricing hai, done.
- Sirf jahan koi specific model tier ke normal price se different ho (kabhi kabhi), wahan **ek chhota sa override** add karo — baqi sab tier ka price inherit karta hai.
- Chahen to country-level override bhi upar isi system pe add ho jata hai.

Isse 7,840 manual entries → **160 base prices + handful of exceptions** ban jati hain. Models ko tier assign karna bhi automate ho sakta hai (naam pattern se — "Pro Max/Ultra" = Flagship, "SE/Lite" = Economy — script se auto-tag, phir aap sirf review karo).

Detailed engineering spec (tables, resolution logic, admin screens, migration steps, aur competitor feature-gap list) neeche wali MD file mein hai — yeh Antigravity ko directly dene ke qabil hai.
