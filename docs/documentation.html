Overview & Architecture

Enterprise architecture and system boundaries

The Repair Booking Form is a modular WordPress plugin built for electronics repair shops, service centers, and enterprise franchises. It provides an intuitive multi-step booking widget on the customer frontend and an administrative suite for managing brands, device models, repairs, supplier wholesale feeds, exchange rates, and customer orders.

📱 18 Real Device Brands

Pre-populated catalog covering Apple, Samsung, Google Pixel, OnePlus, Huawei, Xiaomi, Oppo, iPad, MacBook, Vivo, Realme, Infinix, Tecno, Honor, Motorola, Nokia, Nothing / CMF, and Others.

💰 Dynamic Margin Pricing

Customer prices calculate live from wholesale supplier feeds (LXCell) or Tier default prices using the formula: (Cost + Labour) * (1 + Markup%) * (1 + Tax%).

🧾 Single-Page Receipt / Invoice

One-click thermal / A4 printable receipt formatted strictly for a single page with company header, QR verification code, breakdown, and VAT registration.

🔄 Automated 48-hr Wholesale Sync

Background WordPress cron syncs supplier catalog prices automatically with zero-downtime concurrency mutex locks and out-of-stock tier fallbacks.

Plugin Entry Point: repair-booking-form.php encapsulates plugin initialization, constants, database lifecycle hooks, and administrative routing.

Installation & Setup

Quick deployment instructions
  1. Upload & Activate Plugin

    Upload the repair-booking-form directory to your WordPress installation's /wp-content/plugins/ directory. Activate the plugin via WordPress Admin → Plugins.

  2. Automatic Database Initialization

    Upon activation, RBF_Catalog::get_instance()->install() automatically provisions all 9 custom database tables and populates the default 18 brands and 400+ device models.

  3. Place the Booking Shortcode

    Create or edit any page (e.g., /book-repair/) and insert the primary shortcode: [repair_booking_form].

  4. Configure Currency & Payment Gateways

    Navigate to Repair Booking → Currency & Rates and Payment Settings to configure AED / USD rates, Stripe, PayPal, or Cash on Delivery.

4-Step Frontend Booking Flow

Customer booking experience breakdown
  • Step 1: Select Brand

    Customers select from 18 top brands with authentic official logos. A live search bar allows instant filtering (e.g. typing "Google" or "Xiaomi").

  • Step 2: Select Device Model

    Models are displayed with high-resolution imagery and organized by series (e.g., iPhone 17, Galaxy S24, Pura 70, Mi 14). Sub-series selection ensures customers find their exact device.

  • Step 3: Select Repairs (4-in-a-Row Square Cards Grid)

    Repairs are presented in a responsive 4-column square card grid. Each card displays the repair icon (screen, battery, charging port, camera, water damage), title, warranty badge, duration, and dynamic customer price. Customers can toggle multiple repairs into their cart.

  • Step 4: Contact & Service Fulfillment Selection

    Customer enters contact details (name, email, WhatsApp phone, address) and chooses service type:
    • 🚚 Pickup & Delivery
    • 🏠 Onsite Home Service
    • 🏪 Visit Our Store

    • Server-Side Price Validation: At Step 4 submission, client-submitted prices are discarded and recalculated directly from the database server-side to prevent tampering or manipulation.

    Single-Page Invoice & Receipt Printing

    Strict single-page print engine for receipts and workshop orders

    Upon booking completion, customers and shop staff can click 🧾 Print Invoice / Receipt. The print engine isolates only the confirmation card and excludes page headers, navigation menus, sidebars, and footers.

    • Strict 1-Page Constraint: Scaled specifically via @media print and page-break-inside: avoid to prevent spilling onto page 2.

    • VAT Compliance: Displays Subtotal, VAT rate (5%), VAT amount, and Grand Total with TRN / Tax registration placeholders.

    Executive Modal & Popup System

    Zero-FOUC, blur backdrop, and reliable dismiss button architecture

    All modals throughout the admin suite (Add Brand, Edit Brand, Add Model, Edit Model, Add Booking, Booking Details) utilize a unified modern design system.

    Key Modal Rules (v2.0.6):

    • Default Hidden State: Modals are styled with display: none; by default, preventing blank popups or dark screen overlays on page load.
    • Active State: Modals activate via display: flex !important; when the .active class or inline display is applied.
    • Distinct Dismiss Button: The circular top-right close icon uses class .rbf-modal-dismiss-btn (isolated with position: absolute; top: 20px; right: 22px; width: 34px; height: 34px; border-radius: 50%).
    • Footer Action Buttons: Footer buttons (Cancel, Close, Save) maintain static positioning (position: static !important; width: auto !important; border-radius: 8px !important), completely preventing button overlap.

    Pricing Engine & Mathematical Formulas

    Dynamic supplier cost margin calculations and tiered fallbacks

    The pricing engine resolves the final customer price through an ordered 3-stage hierarchy:

  • Stage 1: Manual Override (Highest Priority)

    If an administrator has explicitly set a custom price in Repair Prices (marked with is_admin_edited = 1), this price locks and overrides all supplier feeds and formulas.

  • Stage 2: Live Supplier Price (Wholesale Formula)

    If a supplier SKU mapping exists (e.g. LXCell SKU LX-IP15-SCR) and is verified in stock, the price is evaluated via:

    Customer Price = (Supplier Wholesale Cost + Labour Fee) × (1 + Markup Percentage) × (1 + Tax Percentage)

    Example: Wholesale cost AED 300, Labour AED 80, Markup 13%, Tax 0% → (300 + 80) × 1.13 = AED 429.40.

  • Stage 3: Tier Default Fallback

    If the supplier is out of stock or no mapping exists, the system automatically falls back to the model's device tier default price (e.g., Flagship Tier 1 Screen = AED 450, Tier 2 = AED 320), ensuring customers can always complete checkout.

    Automated Supplier Sync (LXCell)

    Wholesale feed parser, OpenXML engine, and background cron

    The plugin integrates natively with wholesale spare parts distributors (such as LXCell) to continuously keep replacement part costs accurate.

    Engine Capabilities:

    📄 Dual Feed Parsing

    Native streaming parser for CSV feeds and pure PHP ZipArchive OpenXML parser for native Excel .xlsx spreadsheets without requiring heavy external Composer packages.

    ⏰ 48-Hour Background Cron

    Automated schedule registered via wp_schedule_event on hook rbf_supplier_price_sync running every 172,800 seconds.

    🔒 Mutex Concurrency Lock

    Uses WordPress transients (rbf_supplier_sync_lock) to ensure parallel cron workers or admin clicks cannot execute overlapping imports.

    🛡️ Zero Data Leakage

    Wholesale part costs, labour margins, markup multipliers, and supplier identities are strictly isolated from all frontend responses.

    Troubleshooting & FAQs

    Common questions and diagnostic resolutions

    Q: Why was an empty popup or dark screen showing on the Bookings page?

    A: In prior versions, assets/css/admin.css had .rbf-modal { display: flex !important; }. This forced hidden modals open on page load. In v2.0.6, modals are styled with display: none; and only activate when .active or display: flex is explicitly set by click events.

    Q: Why did the close button have "Close" or "Cancel" overlapping with the ✕ icon?

    A: The CSS selector .rbf-modal-content .close-modal previously targeted both the top-right dismiss button AND the modal footer's "Close" / "Cancel" button. In v2.0.6, the top-right button uses .rbf-modal-dismiss-btn, while footer buttons use static positioning.

    Q: How do I force the browser to reload newly updated brand logos?

    A: All logo image tags now include ?v=2.0.6. Hard refreshing the browser (Ctrl + F5 or Cmd + Shift + R) or bumping RBF_VERSION in repair-booking-form.php immediately refreshes all client and admin browsers.

    Q: How do I verify the background supplier price sync is running?

    A: You can check scheduled cron jobs using WP-CLI (wp cron event list) or plugins like WP Crontrol. The hook is rbf_supplier_price_sync, running every 48 hours. You can also trigger an immediate sync by clicking Sync Now under Repair Booking → Repair Prices.
