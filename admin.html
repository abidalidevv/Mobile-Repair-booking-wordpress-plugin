Plugin Description

The Repair Booking Form Plugin is a comprehensive WordPress solution designed for mobile device repair businesses. It provides a multi-step booking form, admin management system, and automated pricing management for repair services.

Key Features

📱 Multi-step Booking Form

Customer-friendly form with device selection, service choice, and payment integration

⚙️ Admin Management

Comprehensive admin interface for managing brands, models, repairs, and bookings

💰 Dynamic Pricing

Advanced pricing system with brand-model combinations and admin overrides

📊 Dashboard Analytics

Real-time booking statistics and status management

🔄 Auto-synchronization

Automatic data sync between JSON source and database tables

🎨 Professional UI

Modern, responsive design with intuitive user experience

System Requirements

  • WordPress: 6.0 or higher
  • PHP: 8.0 or higher
  • MySQL: 5.7 or higher
  • Browser: Modern browsers with JavaScript enabled

Installation & Setup

Plugin Installation

Step 1: Upload Plugin

Upload the plugin folder to /wp-content/plugins/ directory

Step 2: Activate Plugin

Go to WordPress Admin → Plugins → Activate "Repair Booking Form"

Step 3: Database Setup

Navigate to Repair Prices Management page and click "Setup Database Tables"

Initial Configuration

Important: The plugin requires initial database setup to function properly. This creates all necessary tables and populates them with default data.

Database Tables Created

Table Name Purpose Key Features
rbf_bookings Stores customer booking information Status tracking, payment info, customer details
rbf_brands Device brands (iPhone, Samsung, etc.) Active/inactive status, JSON sync
rbf_models Device models linked to brands Brand relationships, status management
rbf_repairs Repair services and base prices JSON source sync, pricing data
rbf_pricing Brand-model-repair combinations Admin overrides, dynamic pricing
rbf_default_prices Base prices for repair services Master pricing reference

System Workflows & Logic

1. Data Synchronization Workflow

JSON Source Management

Admin updates repair services in JSON file via Repair Services Management page

Database Sync

System automatically syncs JSON data to database tables

Pricing Table Regeneration

Pricing combinations are regenerated based on updated data

Admin Override Preservation

Custom admin prices are preserved during regeneration

2. Booking Creation Workflow

Customer Form Submission

Customer fills out multi-step booking form

Price Calculation

System calculates price based on brand-model-repair combination

Database Storage

Booking information stored with "Pending" status

Admin Notification

New booking appears in dashboard and bookings management

3. Price Management Workflow

Default Price Setting

Base prices set in Repair Services Management

Combination Generation

System generates all brand-model-repair combinations

Admin Customization

Admins can override specific combination prices

Customer Pricing

Customers see final prices during booking

4. Table Regeneration Logic

Regeneration Process: 1. Sync JSON repairs to database 2. Get live data from master tables 3. Define excluded repairs (4 specific services) 4. Filter repairs for combinations 5. Preserve admin-edited prices 6. Clear existing pricing table 7. Insert default prices for all repairs 8. Generate combinations for filtered brands/models 9. Restore admin-edited prices 10. Update status and logging

Excluded Repairs (Not in Combinations)

  • Software Support
  • General Diagnosis
  • Data Recovery
  • Device Unlock Service

Filtered Brands for Combinations

  • iPhone
  • Samsung
  • Google Pixel
  • OnePlus

5. Admin Override Priority System

Priority Order: Admin-edited prices > Default repair prices > System fallback

Price Edit

Admin edits individual price in combinations table

Database Marking

Price marked with is_admin_edited = 1 flag

Preservation During Regeneration

Admin prices backed up before table clearing

Restoration

Admin prices restored with original values

6. Auto-refresh & Synchronization

Dashboard Auto-refresh

Dashboard refreshes every 10 seconds automatically

Status Change Detection

AJAX calls trigger dashboard refresh on status changes

Cross-page Sync

Changes in one admin page reflect in others immediately

Database Structure & Management

Database Tables Overview

Table Purpose Key Fields Relationships
rbf_bookings Customer bookings id, customer_name, brand, model, repair, status, total_amount References brands, models, repairs
rbf_brands Device brands id, name, status, created_at Has many models
rbf_models Device models id, brand_id, name, status, created_at Belongs to brand, has many prices
rbf_repairs Repair services id, name, price, status, created_at Has many prices

Key Database Fields

Status Fields

  • booking.status: pending, in_progress, completed, cancelled
  • brand.status: active, inactive, deleted
  • model.status: active, inactive, deleted
  • repair.status: active, inactive, deleted

Admin Override System

rbf_pricing.is_admin_edited: • 0 = Default price (from repair service) • 1 = Admin-edited price (preserved during regeneration) Usage: • Backup before TRUNCATE • Restore after regeneration • Visual indicators in admin interface

Data Synchronization

Source of Truth

Auto-trigger

Sync Triggers

Troubleshooting & Common Issues

Common Issues & Solutions

1. Dashboard Not Showing New Bookings

Symptoms: New bookings don't appear in dashboard counts

Check Status Field

Ensure new bookings have status = 'pending' (not '0.000000')

Verify Database

Check if bookings table exists and has correct structure

Refresh Dashboard

Use manual refresh button or wait for auto-refresh

2. Prices Showing as 0.00

Symptoms: All prices display as 0.00 instead of actual values

Check JSON Sync

Verify JSON repairs are synced to database

Regenerate Tables

Use "Regenerate All Combinations" button

Verify Repair Prices

Check rbf_repairs table has correct price values

3. Filter Not Working

Symptoms: Advanced filtering doesn't show expected results

Check JavaScript Console

Look for JavaScript errors in browser console

Verify Data Attributes

Ensure table rows have proper data-brand-id, data-model-id attributes

Clear Browser Cache

Refresh page or clear browser cache

4. Admin Prices Not Preserved

Symptoms: Custom admin prices lost after regeneration

Check is_admin_edited Column

Verify rbf_pricing table has is_admin_edited column

Check Regeneration Logs

Look for error logs about price preservation

Manual Database Check

Verify admin prices exist in database before regeneration

Debug Information

Error Logging

Database Queries

Common Debug Queries: -- Check booking statuses SELECT status, COUNT(*) FROM rbf_bookings GROUP BY status; -- Verify admin overrides SELECT COUNT(*) FROM rbf_pricing WHERE is_admin_edited = 1; -- Check repair prices SELECT name, price FROM rbf_repairs WHERE status != 'deleted'; -- Verify pricing combinations SELECT COUNT(*) FROM rbf_pricing;
